# Motion Relay

基于 Python、Vision-Agents、Qwen Realtime 和本地姿态规则的实时 AI 运动教练研究原型。

项目架构、运行方法与功能边界见 [开发分支 README](https://github.com/lyy26299/motion-relay/blob/research/agent-architecture-v2/README.md)。

### 测试条件

- **场景**：`history-12-reps-v1`，预置上一次训练的 12 次有效深蹲记录，输入“上次训练做了几次？”，要求不超过 15 个汉字简短回答。使用本地意图路由、真实记忆检索和真实 Qwen 生成；未覆盖可选的 Laya/Jev 路由。
- **次数**：1 次预热（不计入统计）+ 10 次正式测量；串行、并发 1、无重试，每次新建进程、临时数据库和模型连接；OpenTelemetry 全量采样。
- **模型与环境**：`qwen3.5-omni-plus-realtime`，声音 `Ethan`，服务 `dashscope.aliyuncs.com`；macOS ARM64、Python 3.13.15、OpenTelemetry SDK 1.44.0。
- **完成情况**：10/10 次通过链路完成、检索工具路径与计时完整性检查。此完成率不等同于回答语义正确率，也不是整个 agent 系统的任务成功率。

### 计时与统计口径

端到端从应用收到本轮文本输入开始，到收到模型生成完成事件并处理完本地回执结束，**不包含连接建立和关闭**。首次内容响应取首段非空文字与有效音频中较早者；本批次均为文字先到。`response.created` 只是创建通知，不算首次内容响应。首段音频表示应用收到 PCM 数据，尚未测量浏览器缓冲、网络播放链路和扬声器实际出声；本场景也不包含麦克风采集、ASR 或摄像头/姿态推理。

所有表格按成功的正式测量统计，各指标均为 n=10。P95 使用 nearest-rank，**10 个样本时等于该指标的最大值**，仅作为小样本基线。RTF 为每轮“模型请求至生成完成耗时 / 输出音频时长”的比值，表中平均值是逐轮比值的平均；音频片间隔是每轮最大间隔的分布，不代表实际播放卡顿率。各阶段包含嵌套或重叠区间，不能直接把整张表相加。
