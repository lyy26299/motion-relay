# 教练 Agent 项目审查与可行性结论

审查日期：2026-09-07。对象：当前工作区，含尚未提交的浏览器 AEC 改动。本文新增审查结论，不代表以下问题已修复。

配套设计：[Agent Loop、记忆、MCP 与 RAG 技术设计](./COACH_AGENT_MEMORY_MCP_RAG_DESIGN.md)。

## 1. 优先处理的问题

### R1 / P1：动作真值没有进入应用，提示词却要求精确计数

证据：`agent_local_agent.py:62-66` 要求模型“清晰计数”，`:117-144` 仅挂载通用 `YOLOPoseProcessor`；`coach/models.py`、`geometry.py`、`arbiter.py`、`runtime.py` 目前均为 0 字节文件。

安装的 Vision-Agents 0.6.9 源码中，`plugins/ultralytics/yolo_pose_processor.py:126-131` 得到 `(array_with_pose, pose)` 后仅返回 `VideoFrame`，没有发布 `pose`。`core/agents/agents.py:1064-1084` 会选择处理后的轨道供视频 LLM 消费，因此 Qwen 可能看到骨架叠加图，但没有收到带来源、时间、置信度的关键点事实。

影响：当前“第几个、是否标准、质量评分”主要依赖视频 LLM 和提示词，无法重放核验。直接把这样的输出写入长期记忆，会永久保存未经验证的计数和评价。

建议：一次 YOLO 推理同时输出姿态数据与显示帧，建立跟踪、几何、校准、动作 FSM 和 `RepRecord`。计数及数值统计只接受此链路的产物。当前演示的 LLM 评价应标记为非权威观察。

### R2 / P1：当前 YOLO 处理器的人物编号不能用于记忆归属

证据：SDK `yolo_pose_processor.py:241-255` 遍历 `pose_results` 后使用 `keypoints.data[0]`，把结果列表下标作为 `person_id`。单张图的一个 `Results` 通常包含多个人，这里只取第一人；列表下标也不是跨帧跟踪 ID。

本轮合成诊断：向处理器提供一个含两组关键点的结果，输出 `persons` 数量为 1。诊断没有加载模型、采集设备或调用云端。

影响：另一人进入画面、检测排序变化时，可能把不同人的动作拼成一次完整动作，并将错误结果归入同一训练历史。

建议：项目内 Pose Adapter 遍历每个人的关键点与检测框，独立建立短期 track ID；首版限定单人，出现身份歧义立即暂停当前计数。用户档案由本地档案选择绑定，不能用 `person_id=0` 或浏览器 participant ID 当作用户身份。

### R3 / P1：MCP 工具注册与 Qwen 的实际工具调用之间存在缺口

证据：SDK `core/mcp/mcp_manager.py` 能将 MCP 工具放入 `llm.function_registry`，但当前 Qwen `connect()` 的 session payload 没有工具定义，事件循环也没有函数参数完成、执行、结果回填处理。应用构造 `Agent` 时没有配置 `mcp_servers`。

另外，Qwen `simple_response()` 在 SDK `plugins/qwen/qwen_realtime.py:117-125` 直接返回空结果；项目 `DuplexQwenRealtime` 只覆盖事件处理和关闭，没有增加文本桥。

影响：仅增加 `Agent(mcp_servers=[...])`，不能使当前实时模型自动查询记忆。把 RAG 文本交给 `simple_response()` 也不会实际送达。连接日志中的“registered”不能作为完整 Agent Loop 的验收证据。

建议：应用编排器持有 MCP Client，执行受限查询并校验结果，Qwen 通过项目内文本桥获取上下文。若以后直接开放 Qwen 原生工具调用，必须先验证模型、端点、工具 schema 和完整往返事件，不能从 SDK 基类能力推断。本轮读取的阿里云官方客户端事件文档确实列出 tools 与 function_call_output；这里的缺口是当前适配器和接线，不是断言模型后端不支持工具。

### R4 / P1：提示词把 COCO 17 点无法直接测量的属性写成确定结论

证据：`docs/COACHING_INSTRUCTIONS.md:59-88` 要求判断脚尖方向、脊柱中立、脚跟离地。COCO 17 点没有脚尖、脚跟或脊柱分段点。肩髋的 2D 投影也不能证明骨盆倾斜、脊柱曲率或疼痛原因。

影响：模型可能发出缺乏观测依据的纠正，并把“膝内扣、脊柱异常”等结论固化成用户长期属性。长期检索会让这类错误反复出现。

建议：建立可观测性矩阵。侧面膝角和动作时长可作为带条件的测量；正面双膝距离只能称为投影代理指标；疼痛来自用户自述；不能可靠测量的属性保持 `unknown`。现有知识库需审核后入库，不能直接全文向量化并视为权威知识。

### R5 / P2：每次启动创建空的内存对话，没有跨会话记忆或稳定用户 ID

证据：`coach/browser_edge.py` 的 `create_conversation()` 返回 `InMemoryConversation(instructions=..., messages=[])`；`agent_local_agent.py:147` 每次生成新 call ID。`SessionSettings` 仅包含动作和目标次数。提示词 `COACHING_INSTRUCTIONS.md:615-617` 却要求“记住用户的进步”。

影响：重启无法回答“上次做了多少”，同一会话里的聊天文本也没有结构化的 YOLO 证据。日后若直接以浏览器固定 ID 建库，还会混淆使用同一电脑的不同用户。

建议：新增用户档案、训练会话 ID、同意范围及 SQLite 事实账本。对话缓存、训练工作状态、长期训练记录分别管理。历史未提供时不得生成“上次”的细节。

### R6 / P2：原入口与打包配置指向不存在的模块

证据：`run.sh:68-71`、`scripts/run.sh` 调用不存在的 `vision_agent_demo.py`；`pyproject.toml:30` 和 `:39` 仍引用 `vision_agent_demo`。README 的主要启动说明也沿用旧的 Stream/Gemini 路径。

影响：按首页启动流程或按现有 entrypoint 部署会失败；构建产物不会按预期包含桌面入口，指令文档在安装目录的定位也没有完整打包验证。

建议：明确桌面启动入口，更新脚本、README 和 package data，并在空目录验证安装后的入口与指令资源路径。后续“带记忆 MVP”验收必须包含安装后冷启动。

### R7 / P2：初始化取消与运行时失效缺少闭环验收

证据：`agent_local_agent.py:98` 在关闭时只等待 8 秒；`:117` 的模型构造在 `asyncio.to_thread()` 中。取消 await 不会停止已运行的线程，构造完成后若结果未被接收，调用者没有 `processor` 可关闭。当前控制器也只等待手动停止或 BrowserEdge 结束，没有把 Qwen 健康状态映射到独立的降级状态。

影响：模型慢加载时关闭窗口，进程可能继续运行；云端失败时界面可能仍显示“训练中”。未来记忆写入或摘要任务也可能在关闭时丢失或继续产生过期结果。

建议：为模型加载建立明确的结果接管与清理机制，必要时使用独立进程；添加 session generation、关闭期限和后台任务 drain。UI 分开显示本地动作、云端语音、记忆写入状态。

| `COACHING_INSTRUCTIONS.md` | 中文短反馈、观察不确定性、安全优先 | “没提问保持安静”与主动纠正冲突；观测边界、历史记忆、精确计数需与真实能力对齐；训练知识需审核 |

还需纠正原路线中的几何细节：`x/width, y/height` 适合存储归一化位置，但在非正方形画面里直接用它计算欧氏角度会改变角度。计算角度须还原像素比例，或将两个轴按同一尺度归一化。摄像头镜像与左右身体部位也必须分别处理。

附件中的角色指令、实施建议和未来能力声明只作为待审材料；本次用户请求是项目审查、技术文档与可行性分析。

## 3. 本轮验证与证据边界

本地版本：Python 3.13 环境，`vision-agents==0.6.9`、`ultralytics==8.4.123`、`mcp==1.29.1`、`pydantic==2.13.5`、SQLite 3.50.4。MCP 是当前环境已有的依赖能力，项目尚未接线。

执行：

```bash
.venv/bin/python -m unittest discover -s tests -v
```

最终结果：14 项全部通过。初次运行有 2 项被沙箱监听端口限制阻挡；权限更新后完整重跑通过。没有把环境限制误记为代码缺陷。

同时运行 `.venv/bin/python scripts/smoke_browser_aec.py`，真实 Chrome 使用独立临时配置与虚拟设备，Qwen 使用离线替身。结果：AEC 设置为 true，音视频上行、音频下行都有流量，96 个上行 PCM 帧、95 个 Agent 音频输入帧、1 个视频输入帧，停止清理成功。帧数依调度变化，不作为固定期望值。

本轮没有真人设备、真实 AEC 声学效果测试或 Qwen 云端复测；上述测试不能证明真实运动识别准确率或房间中的回声抑制质量。

另执行无网络、无模型权重的合成诊断，得到：

```text
two_detections_output_persons=1
video_path_return_type=VideoFrame
text_override_present=False
```

这分别验证 R2、R1 的数据出口和 R3 的文本继承路径；不代表真实 YOLO 检测准确率。导入依赖时出现 AV/PyAV 与 OpenCV 重复原生类警告，本次没有观察到崩溃，不能直接认定为故障原因。

`tests/test_setup.py` 是命令行检查脚本，其普通函数不由 unittest discovery 作为测试用例执行。因此“14 项测试”不包括旧启动脚本与打包验证。没有运行该脚本的密钥检查，避免它输出密钥前缀。

现有 AEC 文档中的离线测试与 Chrome 冒烟已在本轮重新确认；Qwen 多模态文档中的云端输入验证仍属于既有证据，本轮未调用付费 API。

本轮在线核对了 MCP SDK 主分支/v1.x 文档、MCP 2025-11-25 Tools 规范、Ultralytics Results 和阿里云 Realtime/客户端事件页。特别发现：MCP Python SDK 当前主线已是 v2，项目安装的是 v1.29.1；应直接锁定版本。阿里云概览与客户端事件页对 input_text 的说明仍不一致，集成必须保留现有端点的契约测试。官方页面内容核对不等同于云端实测。

## 4. 可行性判断

| 目标 | 判断 | 前提与限制 |
| --- | --- | --- |
| 单人、固定机位深蹲计数 | 高可行 | 完成关键点出口、跟踪、校准、FSM 和真实标注重放 |
| YOLO 数据加入短期及长期记忆 | 高可行 | 先保存结构化事件、单次动作统计、来源版本；持久化不依赖 LLM 成功 |
| 下次训练恢复历史与偏好 | 高可行 | 稳定用户档案、事务写入、可比较的训练条件、删除机制 |
| MCP + 个人历史 / 教练知识 RAG | 高可行 | MCP 由编排器实际执行；数值走 SQL，语义走检索；中文索引要实测 |
| 边运动边进行多步骤工具推理 | 中等可行 | 工具调用限步、限时；实时动作不等待检索；轮次控制完成集成测试 |
| 单目 17 点判断全部动作错误或伤病 | 不满足当前观测条件 | 需限制结论，部分任务需要额外视角、足部/全身模型或专业评估 |
| 根据长期记忆自动证明训练建议有效 | 暂不能承诺 | 有前后指标不等于因果证据；需持续采样、比较条件和人工审查 |

建议保留现有浏览器媒体和 Qwen 表达层，新增本地运动事实链路与记忆服务，完成一个深蹲垂直切片后再扩展动作。当前主要工程风险是观测质量与轮次调度，数据库和向量检索本身不是瓶颈。

实施量级、数据契约、MCP 工具及验证门详见[配套设计](./COACH_AGENT_MEMORY_MCP_RAG_DESIGN.md)。本轮产出仅为技术文档，没有修改现有运行代码或上述附件。
